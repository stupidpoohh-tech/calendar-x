# 잔고캘린더 생활비·세이브 반영

기준: Calendar-X 기본 브랜치 63b9736. tide-over 저장소는 계속 리다이렉트 전용이다.
이번 변경은 src/pages/Tide 안에서만 동작하며 로그인·Firebase·Recovery를 추가하지 않는다.

## 사용 흐름

- 머리 카드의 ‘생활비 · 세이브’를 펼쳐 예산(기간·총액)과 확보할 돈을 추가·수정·삭제한다.
- ‘사용 기록’ 또는 항목 편집의 ‘사용처’로 한 번짜리 지출을 생활비에 연결한다.
- 예산 안에서 쓴 돈은 한도를 다시 깎지 않고, 초과분만 추가 차감한다.
- 예산을 지우면 지출은 남고 일반 지출로 돌아간다. 기간 밖·반복·입금도 일반 계산이다.
- 카드·날짜별 한도·일반 예정과 생활비 예약 내역이 같은 계산을 따른다.
- 기존 ‘기간’ 지출은 그대로다. 새 생활비 예산으로 자동 변환하지 않는다.

## 저장·백업

/tide 전용 스키마 v5는 예산과 세이브, 지출의 연결 ID를 모두 저장한다.
v1~v4 백업을 읽을 수 있으며 새 배열을 빈 값으로 추가한다.
v5에서 새 배열이 없거나 원시 데이터의 날짜·금액·중복 ID가 잘못되면 복원하지 않는다.
잔고는 음수 정수도 허용한다. 이전 버전의 앱은 v5를 미래 버전으로 거절한다.

본앱 JSON 백업과 /tide 링크 백업은 별개다. 서로 가져오거나 자동 동기화하지 않는다.
기존 로컬 저장 한계(브라우저 데이터 삭제, 저장 공간 부족)는 유지되며 백업 링크가 필요하다.

## 검증

- 본앱과 /tide의 동일 입력에 대한 계산 비교, 예산 안·초과·정산·삭제·기간 밖 회귀
- 원시 백업의 잘못된 날짜·금액·ID, 구버전 이관, v5 누락 배열, 저장·백업 왕복
- 화면에서 생성 → 지출 연결 → 월 이동 → 수정·삭제 → 재접속·복원
- 실제 브라우저에서 해시 복원 취소/확인, 잘못된 백업의 원문 보존,
  320/390/1280px 레이아웃 및 다크 모드 확인

전체 단위/UI 테스트 621건 통과. 타입·린트(기존 경고 5건)·프로덕션 빌드 통과.
Firestore와 보안 규칙은 변경하지 않았으며 이번 작업에서 에뮬레이터 검사는 실행하지 않았다.
운영 데이터 변경·기본 브랜치 병합·배포는 하지 않았다.
